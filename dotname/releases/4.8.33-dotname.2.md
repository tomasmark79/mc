# Modern Midnight Commander 4.8.33-dotname.2

This release speeds up copying files from ZIP archive panels with F5.

## Changes

- With libzip enabled, MC reads ZIP entries directly through its normal copy
  loop, avoiding a separate extraction process and temporary file for each entry.
- The ZIP helper caches filename mappings for each open archive, reducing repeated
  archive listings when the helper path is used. Changed archives invalidate the
  cache, and MC removes the cache when it closes the archive.
- Custom ZIP helpers, editing, and unsupported entries retain the helper path.
  Builds without libzip remain supported but do not provide the direct-read speedup.
- Source builds consistently report the fork release version, including builds
  from Git checkouts and source trees containing an older generated version header.

## Build requirements

Direct ZIP reads require **libzip 1.0 or newer at build time**. Configure detects it
automatically. On Debian, install `libzip-dev` before configuring and compiling.
Installing the library after compilation does not enable the feature: run configure,
build, and install again. Check `config.h` for `#define HAVE_LIBZIP 1`.
The Nix package includes libzip automatically. See the main README for full build
instructions and other dependencies.

## Performance and validation

In a local F5 extraction benchmark, a ZIP containing 292 files (about 1 GB unpacked)
took **3.1 seconds** with direct libzip reads, compared with **15.7 seconds** using
the cached helper and **4.8 seconds** with standalone `unzip`. Every extracted file
was checked for size and CRC. Timings depend on the archive, hardware, and filesystem.

Validation covers 19 runtime tests and 10 ZIP helper tests, including changed
archives, corrupt data, filename aliases, custom helpers, and background copying.
Nix builds with and without libzip passed; both supported Nix architectures passed
evaluation. Debian compilation has not been tested directly.
